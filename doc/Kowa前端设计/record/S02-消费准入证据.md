## 2. 逐操作的 Producer → Transition → Consumer

约定：`P` 为真正产生事实的 producer 入口（HTTP 路由到服务方法），`T` 为把持久事实映射为 Web 投影的 transition（服务端每次重新判定授权、版本与门禁），`C` 为本阶段实现的消费点。前端只消费已冻结字段，不新增语义、不复制授权、不缓存权威。

**验收解耦（真实 producer 行为，`CODE_CONFIRMED`）**：`human.response` 只把**任务答复**收下（200 `RESOLVED` + 续接意图），知识冻结由 backend:S06 消费续接意图时执行（`internal/orchestration/nodes.go:550 applyAcceptedAnswer` → `internal/orchestration/knowledge.go:82 knowledgeSelection`）。因此：

- 版本/对象漂移的答复 → HTTP 409 `VERSION_CONFLICT`，请求保持 `OPEN`（前端"重取请求 + 显式确认"路径的真实反例）。
- 选择丢弃 `required` 条目或含索引外路径的答复 → HTTP **200**（任务变 `RESOLVED`），但 `knowledgeSelection` 以 `ErrPolicyBlocked` 拒绝**冻结绑定**：不产生快照/绑定事件/有效输入，运行保持 `knowledge_confirm` 等待且不派发任何 Task。前端据此呈现"服务端已接受答复、冻结绑定尚未建立"，绝不显示为已确认；恢复此类运行属后续阶段的恢复交互（frontend:S04，`run.recovery`）。
- 只读预检 §6 的"`required` 不可删的 422 呈现"与上述真实行为不一致（预检预期的是答复被拒），属预检的推断偏差；本阶段以真实 producer 行为为准并在此登记，见 [record/S02](S02.md) 的执行结果与发现分类。
