**色板（4—6 个核心值，全部取自 @primer/primitives，浅色=GitHub Light / 深色=GitHub Dark）**

| 角色 | 浅色 | 深色 | 用途 |

| canvas default | `#ffffff` | `#0d1117` | 卡片、表格、页头表面 |
| canvas subtle / inset | `#f6f8fa` | `#151b23` | 页面画布、Box 页眉、代码块 |

状态色克制且语义唯一：success `#1a7f37` / attention `#9a6700` / danger `#d1242f` / done `#8250df`，每个配一个 muted 衬底与描边（深色对应 Primer 深色阶）。**唯一派生值**是主按钮 hover（`color-mix(--primary 90% → --foreground)`），原因与规则写在生成器注释里：Primer 没有 accent 的 hover 令牌（GitHub 自己的实心主按钮是绿色）。

**字体**：Primer 原栈——正文 `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans", …`，机器事实 `ui-monospace, SFMono-Regular, Menlo, Consolas, …`。字阶（Primer functional）：caption 12/1.25、body 14/1.5、body-large 16/1.5、title-small 16/600、title-medium 20/600、页面标题 24/600、代码 13/1.5；控件高 32px（Primer medium）。密度是本阶段的显式选择：更紧的表格与表单、更小的圆角（6px；标签 2em）。

**独特的那个元素（其余保持安静）**：机器事实一律等宽——状态标签把原始枚举与中文标签并列（`未关闭（OPEN）`）、运行 id/摘要/路径/能力用 `code`；控件、状态色与动效克制，页面里唯一"有颜色"的只有状态标签与通知。这条既是 Kowa 的诚实性要求（投影不得被误认为事实），也是本阶段统一视觉的锚点。

**对照 brief 后的修订（critique）**：① 不做居中大卡片式的登录页——把它收成画布上的一块 Box，保持 shell 的连续；② 不用 Tailwind 默认的圆角/阴影/字号尺度，改为把 library 默认尺度整体重定向到 Primer 步进（`text-sm→14`、`rounded-md→6px`、`shadow-*` 不用）；③ 状态标签用 GitHub Label 的 tinted 面而不是实心色块，避免页面出现大面积彩色；④ 图标只用于通知与页面级动作，且一律 `aria-hidden`，不引入装饰性图标雨；⑤ 预览图里的旧品牌色（黄）与示例业务数据一律不照搬。

#### 执行结果

- 换基方式：Tailwind CSS v4 由 `@tailwindcss/vite` 接入（应用与 `tests/browser` 夹具两处，后者因挂载生产组件也需要 `@` 别名）；主题令牌不手写，而由 `scripts/generate-github-theme.mjs` 从 `@primer/primitives@11.10.0` 的 GitHub Light/Dark 令牌文件生成 40 个颜色 × 3 个块 + 27 个尺度令牌到 `src/styles/github-theme.css`；`src/styles/global.css` 成为唯一样式入口，把 Tailwind 默认字号/圆角步进重定向到 Primer 步进并重置颜色命名空间。组件库经官方 CLI（`npx shadcn@latest add …`）落成 10 个基础组件到 `src/ui/`，Kowa 在其上只做组合件。全部页面（登录、Workspaces、设置、Runtime 列表/详情、工作项列表/新建/详情、知识确认、AppShell/导航/主题控件）迁移完毕，旧的 `tokens.css` 与手写类名集合整体删除，不留兼容层。
- 实际根因或设计发现（按发现顺序）：
  0. **表头里的 `<code>` 会遮蔽冻结旅程的"首个 code"约定（`CODE_CONFIRMED`）**：控制面旅程用 `page.locator('code').first()` 从设置页读取 workspace id（该约定写于 S01/S02 时期，当时页头没有 `code` 元素）；迁移把会话身份写成 `<code>{githubUserId}</code>` 后，首个 `code` 变成了**用户 id**，`ensureWorkspace` 于是返回 `101`，后续所有读取都 FORBIDDEN。**只有真实控制面模式能暴露它**（fixture 模式的 helper 直接返回固定 workspace），因此这条由控制面套件在迁移后第一次跑到时抓到。修复：表头身份改用等宽 `<span>`（视觉与可读文本不变），恢复迁移前的 DOM 契约，不改任何冻结规格；同时确认全仓只有这一处结构性选择器依赖。
  0b. **Tailwind preflight 去掉了链接下划线，暗色下正文内链接只剩颜色区分（`CODE_CONFIRMED`）**：控制面模式的新建工作项页（新工作区未绑定仓库）会渲染"缺少项目仓绑定"警告，其中含指向 Workspace 设置的行内链接；暗色主题下链接色 `#4493f8` 与正文 `#f0f6fc` 只有 2.84:1，命中 axe `link-in-text-block`（要求 3:1）与 `link-in-text-block-style`（无下划线等非颜色区分）。fixture 模式的同一路由有仓库绑定、不渲染该通知，因此只有控制面能暴露。修复：基础层恢复 `a { text-decoration: underline }`（迁移前浏览器默认即如此），控件/导航/标题链接显式 `no-underline`（含入库 Button 基类，使 `asChild` 链接按钮不带下划线）。
  1. **颜色过渡会被工具读到中间态（`CODE_CONFIRMED`）**：入库组件的 `transition-colors` / `transition-[color,box-shadow]` 让主题切换期间的元素颜色处于明暗之间的插值（axe 读到 `fgColor #44484d` on `#0d1117`，对比度 2.05，93 个节点）。确定性链路本身合法（最终色符合 AA），但"切换瞬间"是可被测量的真实状态，因此移除全部颜色过渡（GitHub 本身也是瞬时切换），动效只留加载指示并按 `prefers-reduced-motion` 关闭。
  2. **控件默认宽度会撑破 320px/200%（`CODE_CONFIRMED`）**：库组件默认 `whitespace-nowrap` + `shrink-0`，在 200% 文字下"使用 GitHub 登录"按钮宽 276px + 容器内边距把文档推到 349px（门禁 `scrollWidth <= innerWidth` 红灯）。最小修复落在组件层：去掉 `whitespace-nowrap`（标签可换行）并加 `max-w-full`（控件永不宽于给定空间），不改任何断言。
  3. **Testing Library 与 Playwright 的文本匹配语义不同（`CODE_CONFIRMED`）**：Testing Library 的 `getByText` 只看**直接文本节点**，把 `当前版本 v3` 的 `v3` 单独包成 `<code>` 会让 `/当前版本 v3/` 失配（本阶段实际踩到并按此规则回退）；Playwright 取**最内层**匹配元素（先以最小用例实测确认，再据此保留"整值包一层元素"的写法）。两条规则已写入验证规则，供后续阶段复用。
  4. **jsdom 没有 `ResizeObserver`（`CODE_CONFIRMED`）**：组件库的复选框宿主依赖它，单测因此无法挂载；在 `tests/unit/setup.ts` 加最小桩（引擎都有该 API），不削弱任何断言。
  5. **原生 `<select>` 是两处下拉的必要形态（`CODE_CONFIRMED`）**：外观与成员角色被既有旅程用 `selectOption`/`toHaveValue`/`toBeFocused` 驱动，这些语义只存在于原生控件；改为 listbox 会把冻结断言改写成另一套交互模型，超出"最小选择器更新"。因此保留原生控件并套用同一套令牌外观（`src/ui/Select.tsx`），其余控件全部来自组件库。
  6. **`doc/当前进展.md` 的 lease**：开工时该共享投影的独占 lease 在 backend:S07 worker 手中（Coordinator 裁决），本阶段不触碰该文件；收口时再申请（见下）。
