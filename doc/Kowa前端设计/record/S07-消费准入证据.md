## 4. 本阶段消费要点（约束的来源）

- **全页面 28 个操作都要在真实控制面上跑通**：S07 的真实控制面 E2E 必须按页面对齐到 operation，不能只覆盖「有写操作」的页面。
- `journey.closure` 不受约束 → 不消费；页面不得出现第二个关闭权威。
- `workitem.cancel` 无调用者：取消运行只走 `run.recovery` 的 `cancel` 命令，页面不直接取消工作项。
- `runtime.view` 是 Runtime 详情页（`/workspaces/{id}/runtimes/{runtimeId}`）的唯一读取，也是 S06 遗留登记项 ⑨ 交还 S07 的常驻 axe/窄屏用例所在页面。
- `fixed.workflow` 是 DAG 的边与拓扑序的**唯一**来源（`run.detail-history` 的节点轮次没有边）；DAG 的无障碍表达（每个节点是真实按钮 + `aria-describedby` 写出依赖）必须在 axe 与键盘旅程中同时守住。
- `observability.watermarks` 的 `lastAttemptKnown=false` 只说明最后一次读取失败；页面不外推最后成功时间（沿用 S06 §4）。
- **消费者缺口（登记，不在本阶段实现）**：`kowa.web-application.v1` 的 `workspace.list` 已由 backend:S06 交付并 `DONE`，但 `WorkspacesPage` 至今没有调用它——该页只提供 `workspace.bootstrap` 与「用已知 ID 打开」。这属 S01 记录的「工作区列表/发现」消费者缺口的延续：owner 侧已补上操作，消费侧未接。S07 的合同边界（响应式/可访问性收口 + 端到端验收，`允许修改` 不含新增页面能力）不覆盖它，故只登记：**若后续阶段要显示「当前身份可读的工作区集合」，应消费 `workspace.list` 而不是在本地记忆工作区 ID**。本阶段不新增任何本地记忆，页面现行为保持不变。
