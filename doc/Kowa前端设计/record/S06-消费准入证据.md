## 2. 逐操作的 Producer → Transition → Consumer

## 4. 本阶段消费要点（约束的来源）

- `delivery.query` 的 `facts` 是**每主体最新一条**且 `unknown=true` 的行不带 payload：失败的读取既不是事实也不是“不存在”，页面必须单独列出并写清原因；「最后成功观察时间」只能取成功读取的 `observedAt` 最大值。
- `delivery.query` **没有**任何合并/批准/关闭写操作；`operations[].kind` 只有 `verify_change` 与 `publish_pr`。页面据此不提供第二个合并批准按钮。
- Review 的**适用提交**是 `review.commitOid` 与 PR 观察到的 `pullRequest.headOid` 的比较；缺任一侧即“适用提交未知”，不得当作适用。
- `checks.state` 的四值是 `none|pending|failed|passed`，`none` 不是通过（README 明文）。
- `verification.source` 的 `simulated` 不满足门禁；`knowledge_suggestion`/`offline_evaluation` 是辅助事实，失败不阻塞关闭。
- `observability.watermarks` 的 `lastAttemptKnown=false` 只说明最后一次读取失败；该主体最后一次成功读取的时间**不在**该水位里，页面不外推。
- 外链只由 `workspace.config` 的项目仓 `displayName`（须已是 `owner/repo` 形状）+ 数字仓库 ID 一致性共同放行；任一不满足即不渲染链接。
