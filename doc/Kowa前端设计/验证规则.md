# 前端验证规则

本文定义前端阶段共享的最低验证口径。阶段文件必须把适用条目落实为精确命令，全部结果写入对应 `record/Sxx.md`。

## 1. 开工冻结

至少记录：

```bash
git rev-parse HEAD
git status --short
bash scripts/check-doc-governance.sh
mise exec -- node --version
mise exec -- pnpm --version
```

修改页面、组件、样式或交互前，还必须阅读 `总体设计与进度.md` 与 `web-preview-reference/index.md`。

## 2. 自动验证层次

按风险依次执行：

1. 修改既有行为时运行 characterization 测试；纯绿地阶段记录不适用依据。
2. 目标红灯。
3. 修改范围内的单元或组件测试。
4. 类型检查、静态检查和受影响回归。
5. 生产构建。
6. 路由、认证、关键工作流、响应式或可访问性变更对应的端到端测试。
7. 文档治理门禁、`git diff --check` 和必要的人工视觉验收。

前端工程基座建立后，S00 必须在 `package.json` 固化以下脚本入口；在脚本建立前，阶段文件不得假称已执行：

- `pnpm lint`；
- `pnpm typecheck`；
- `pnpm test`；
- `pnpm build`；
- 受影响的端到端测试入口。

## 3. 视觉与契约边界

- 预览图只用于信息架构和交互理解，不是像素级基线。
- Mock 必须绑定正式契约，不能替代 provider 测试或端到端验收。
- 共享契约变更由唯一 owner 阶段冻结；前端消费侧不得自行扩展错误、重试、分页或状态语义。

## 4. 收工检查

```bash
bash scripts/check-doc-governance.sh
git diff --check
git status --short
```

阶段还必须记录定向测试、类型检查、受影响回归、构建结果、退出码、测试数量、视觉偏差、风险和未完成项。

## S00 固定工程命令

精确命令、工具链 PATH 处理、浏览器安装与运行端口见 [Web 工程基座](Web工程基座.md)。本机统一使用 `bash scripts/web-env.sh pnpm <script>`（脚本名为 lint、typecheck、test、build、test:e2e）；CI 使用固定 Node/pnpm 后执行同名命令。

## 合同证据补充

逐操作核对 owner、冻结引用、实际入口和正反证据；样例/Mock 不替代 producer 验证。后端对实际序列化及多适配器不变量做测试，承诺 HTTP 交付时通过组合根验证；前端关键旅程使用真实控制面和隔离外部适配器。拒错后事实保持正确且合法请求仍可成功，真实到期等合同允许的转换另验。

`bash scripts/check-doc-governance-test.sh` 包含阶段依赖/合同绑定及合法重开自测。治理绿色只证明可形式化条件，不证明消费需求完整或业务实现正确。
