# MVP 信息架构

状态：设计草案，未实现；MVP 机器个人 gh 身份与独立 PR 节点已纳入。更新：2026-09-27。

本文件只定义首期页面责任与交互，业务条件引用 [MVP 流程](../wiki/design/mvp-delivery.md)，共享对象引用 [领域设计](../wiki/domain/delivery-lifecycle.md)。[预览参考](web-preview-reference/index.md)用于布局理解，不是功能清单、真实业务数据或像素验收标准。

## 1. 最小页面

| 页面 | 用户完成的事 | 不应承担的事 |
| :--- | :--- | :--- |
| Workspace 配置 | 登记项目/知识仓库，查看 Runner 本机 Provider、个人 gh 身份和验证配置 | 隐藏机器账号权限范围、把两仓默认都设为可写 |
| 工作项列表与创建 | 输入需求，选择目标，查看当前待办和交付结果 | 创建多仓父子编排或任意 DAG |
| 工作项详情 | 查看真实 DAG、当前节点、人工任务、产物与交付 | 在前端另写状态机 |
| 人工任务详情/抽屉 | 阅读依据、调整知识选择、批准/驳回、处置失败 | 自行推断允许动作或绕开版本校验 |
| 运行与版本历史 | 查看节点轮次、旧结果、修复运行和关联工作项 | 将历史查看按钮解释为 Replay |

首期不新增独立部署中心、拖拽工作流编辑器、知识库自动写回入口或 Replay 操作页。

创建工作项只使用一条固定内置工作流，不显示多模板选择。后续增加模板或 Agent 节点以获准的新定义版本呈现，历史 DAG 继续展示其冻结版本。

首轮多人验收只在部署本机的浏览器完成；成员分别用自己的 GitHub 身份登录。页面要展示当前登录者与 Workspace 权限，并在账户切换、会话过期时清理之前账户的可见缓存。`localhost` 的 Web UI 不代表已经支持异地团队访问。

## 2. 工作项详情布局责任

- 顶部：需求与目标仓库、当前交付结果、当前运行与修复关联。
- 主区：DAG 与当前节点；节点展示执行状态、业务结论和阻塞原因，不能只用一种绿色完成标识。
- 待办区：服务端提供的 HumanTask 与恢复动作；关键批准必须能打开所审版本。
- 产物区：知识、方案、代码、测试、评审、PR 与关闭证据；历史版本可见，当前适用性明确。
- 进度区：可观测事件与日志；连接断开显示陈旧状态，不将最后一次消息当作最新真源。

### 页面入口与职责

下列路径是前端导航设计，不是已实现路由或后端 API：

| 入口 | 主要内容 | 动作归属 |
| :--- | :--- | :--- |
| `/login` | GitHub App 登录、会话失效说明 | 服务端 OAuth 回调建立会话 |
| `/workspaces/:workspaceId/settings` | 项目仓、知识库、成员、Runner/Provider 与验证配置 | 仅服务端授权的管理员命令 |
| `/workspaces/:workspaceId/work-items` | 列表、状态与待处理数 | 只读投影，不在浏览器计算阶段结果 |
| `/workspaces/:workspaceId/work-items/new` | 单仓需求、验收标准和唯一固定流程 | 创建命令；无多模板选择 |
| `/workspaces/:workspaceId/work-items/:workItemId` | DAG、当前有效节点、知识/方案/测试/PR/证据和修复运行 | 所有可用动作从服务端返回 |
| `/workspaces/:workspaceId/human-tasks` | 知识确认、方案审批、恢复待办及 GitHub 外部操作提示 | Kowa 内答复提交到 Kowa；外部提示只链接 GitHub 并由对账事实收束，不复制批准按钮 |
| `/workspaces/:workspaceId/runtimes` | 独立 Runner 健康、Provider/gh 账号、Git remote 可用性与权限缺口 | 健康展示与受权的配置入口；不把 gh 已登录等同 push/PR 已可用 |

工作项详情以查询状态保存当前页签和节点选中项，浏览器后退可恢复阅读位置。选中的历史 NodeRun 必须显示“历史轮次”，不能与当前有效结果混色或偷偷给出继续执行按钮。PR 的有效 Review、实际合并、合并后验证分开呈现。

用户切换 GitHub 身份或 Workspace 时，清除跨身份缓存与未提交表单；页面不能仅靠隐藏导航阻止越权。错误、等待、跳过、取消和外部事实未核对均提供文字说明，不能只用颜色或转圈表示。

## 3. 人工交互

知识条目支持推荐、增删、搜索与已选预览；来源和固定版本可见。表单默认值不是确认记录。服务端校验失败时保留用户输入，重新获取最新请求，不自动重试危险决定。

未知必需字段阻止提交；只读字段由服务端约束，客户端禁用不构成安全保证。复杂审阅使用独立页面或足够空间的抽屉，提交栏保持可达；键盘焦点、错误关联和屏幕阅读器标签在实现时验收。

审批对象过期应明确提示并引导重审，不能把旧提交改绑新方案。操作处理中防重复点击只是体验优化，真正幂等由控制面保证。

PR 区域分别展示当前 WorkflowRun 的 Web 发起人、Runner 的个人 gh 执行账号、远端 commit author/committer、GitHub PR 实际创建者、真人 Review 的处理人/结论/适用提交，并提供 GitHub 链接。MVP 提交和 PR 署名应匹配该 Runner 机器账号；Web 发起人与 Agent 生成来源另行标注，不把机器写入冒称 A/B 本人写入。实际 GitHub 身份或版本不符时显示冲突且不放行。合并由人在 GitHub 完成，页面展示 Kowa 对账后的合并事实，不提供第二个合并批准按钮；未核实时显示最后成功观察水位。

必需测试和独立评审通过后，Runner 的独立 `publish_pr` 能力用本机 gh 账号创建 PR。机器 gh 登录失效、目标仓无权或分支受规则拒绝时，页面显示 Runner/GitHub 配置问题并保留已确认的远端提交；不能提示 Web 发起人 A 用其个人授权冒名补救。Coder 理论上可用宿主 gh 提前建 PR；MVP 不为此设计专项页面或自动清理，不能把正常 DAG 顺序展示成 GitHub 层硬阻止。

外部操作型 HumanTask 的待办卡片展示目标 PR、适用 head、所需动作和 GitHub 链接；没有可代替 GitHub Review/合并的 Kowa 提交按钮。Review 必须来自有权真人而非 Agent，且不能由 PR 创建账号自审；Web 发起人若不是 PR 创建账号，可以处理 Review。head 漂移时旧卡片过期，新的待办和适用性由服务端给出。字段形状仍随共享契约审阅，不能从页面实现反推审批权威。

本机首轮通过主动查询 GitHub 更新事实；页面应标明上次成功核对时间与查询失败，不把 SSE 连接不断开解释为 GitHub 状态仍然新鲜。

知识确认页展示候选内容快照及其摘要，提交后关联独立确认记录；同一内容再次确认不必复制快照，但必须能看见新的人工动作。产物可查看不等于已获准供下游使用。

身份与允许动作来自 [身份设计](../research/mvp-identity-security-design.md) 的服务端授权结果；不得把 App installation 成功或 Runtime 在线当作用户已经登录并获批。

## 4. 异常与关闭展示

| 场景 | 必需呈现 |
| :--- | :--- |
| 无相关知识 | 成功读取后的空选择，仍显示确认情况 |
| 知识获取失败 | 失败原因与恢复动作，不显示为“无知识” |
| 返修耗尽 | 已用轮次、反馈、继续/调整/取消入口 |
| 合并后验证失败 | 合并事实与验证失败同时可见，工作项未关闭 |
| 已关闭项新增需求 | 创建关联工作项，不提供原项继续执行 |
| 知识建议失败 | 辅助任务失败与重试入口，不把业务关闭显示成失败 |
| 取消结果待对账 | 不宣称所有外部操作已撤销 |
