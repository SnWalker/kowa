# 测试仓库约定：SnWalker/kowa-sandbox

性质：跨端可复跑验收的环境约定；不维护阶段状态，也**不构成对任何写操作的授权**。真实 GitHub 写入仍按根 `AGENTS.md` §6 由用户执行，除非用户在当次任务中明确授权具体范围。依据与实测见 [S04 前置风险验证 Spike 报告](../research/s04-prerisk-spike-20261002.md)。最近核验：2026-10-11。2026-10-11 用户专项授权将业务沙箱改为 public 并配置分支保护；此前 private-only 约定被此授权替代，知识沙箱仍 private。证据见 [S04 准备记录](../Kowa后端设计/record/S04.md)。

## 1. 用途与边界

`SnWalker/kowa-sandbox` 是 Kowa 整个开发与调试期间用于真实 `git`/`gh` 行为的专用测试仓库：clone、commit、工作分支 push、PR、Review/合并观测、Runner/Provider 运行。它只含一个假数据 Go 包 `calc`，一切内容可丢弃。

- Kowa 的代码、CI、文档与自动测试**不得依赖**该仓库存在或处于特定状态；它只服务于人工授权的真实验收与调试。
- 它在 MVP 里只扮演“业务项目仓库”角色。“知识库仓库（只读）”角色由 `SnWalker/kowa-sandbox-knowledge` 承担，固定基线见 §8。
- 不得用它存放 Kowa 证据；证据写入 Kowa 仓库的 `record/`。

## 3. 分支与标签约定

| 引用 | 用途 | 规则 |
| :--- | :--- | :--- |
| `main` | 全绿的最小基线 | 任何会话**不得**推送、强推、合并到 `main` |
| `fixture/<name>` | 可复用起点（如“修复失败测试”） | 只能从中派生；**不得**向其推送；PR 可以把它作为 base（只建 PR，不合并） |
| `baseline` | 初始提交标签 | 不移动 |
| `task/<id>` | 一次任务/执行尝试的工作分支（Runner 的工作分支） | 实验后删除；`<id>` 用任务或 spike 标识 |
| `exp/<topic>` | 一次性实验 | 实验后删除 |

命名之外的分支视为违规，应在清理时删除。

## 4. 允许与禁止的操作

在用户于当次任务中明确授权后，允许（范围以授权文本为准）：

- 从 `main` 或 `fixture/*` 派生 `task/<id>`、`exp/<topic>`；在其上提交；推送这些**非默认分支**。
- 创建、关闭 PR；删除自己创建的 `task/*`、`exp/*` 分支。

永远禁止（除非用户另行专项授权并修改本约定）：

- 向 `main` 或 `fixture/*` 推送；合并任何 PR；强推；
- 删除或改名仓库，修改仓库设置或可见性，安装/授权 GitHub App，创建 Webhook/Deploy key/Secret，修改账号级设置；
- 修改 Kowa 源仓库或其他任何仓库；
- 打印或泄露令牌、私钥内容。

注意：受控通道不向 Coder 交付远端凭证，但同机同账号仍可能读取宿主个人 gh/SSH 凭证并绕过通道。分支保护为受保护 ref 提供平台约束，不证明其他仓库/分支或凭证已隔离；仓库 admin 仍能改变保护设置。每次会话前后仍须做 §5 的 ref 断言和负向验收，不能依赖提示词。

## 5. 会话预检与收尾（可复跑命令）

预检（只读）：

```bash
gh api repos/SnWalker/kowa-sandbox --jq '{private,visibility}'                  # 必须 public
gh api repos/SnWalker/kowa-sandbox/branches/main/protection                    # 核对 admins/reviews/force/delete
gh api repos/SnWalker/kowa-sandbox/branches/fixture/failing-test/protection    # 同上，且 locked=true
gh api user --jq '{login,id}'                                                   # 必须 SnWalker / 135722937
gh auth status --active --json hosts                                            # login/active/state 符合预期
ssh -o BatchMode=yes -T git@github.com                                          # 必须出现 "Hi SnWalker!"（退出码 1 是正常的）
git config --get user.email                                                      # 与预期作者一致
git ls-remote origin                                                             # 核对冻结 main、fixture/failing-test、baseline；PR #6 已合入，其分支仍保留，未授权不能清理
go test ./...                                                                    # main 通过；fixture/failing-test 必须失败
```

收尾（需授权）：

```bash
gh pr list --repo SnWalker/kowa-sandbox --state open --json number,headRefName
gh pr close <n> --repo SnWalker/kowa-sandbox                                     # 仅关闭本次获准实验；不关闭其他会话的交付
git push origin --delete <task/* 或 exp/* 分支>                                  # 只删除本会话创建的分支
git ls-remote origin                                                             # 断言：main=b99754c…，fixture/failing-test=0a62e29…，refs/tags/baseline=d4943b0…
```

已知残留：关闭的 PR 会保留 GitHub 隐藏引用 `refs/pull/<n>/head`，无法删除；PR 编号只增不减。

## 6. 重置方法

1. 仅关闭并删除本次获准实验产生的 PR/`task/*`/`exp/*` 分支（§5 收尾）；不得清理其他会话的交付或历史分支。
2. `main` 与 `fixture/failing-test` 若被误改，应恢复到上表 SHA：`main` → 上表当前批准 SHA（目前 `b99754c…`），`fixture/failing-test` → `0a62e29…`。`baseline` 仅是初始标签，不含后续已批准文档，不能作为当前 main 的自动回滚目标。
   - [PR #6](https://github.com/SnWalker/kowa-sandbox/pull/6) 已按用户合入授权完成非作者账号批准与 owner 合并，README 已同步 public、保护和当前 main 恢复口径。批准正文明确记录 AI 辅助来源，不能以该准备文档的 Review 证明 S05 真人业务审阅旅程已验收。
   - 恢复 `main`/`fixture/*` 本身是对受保护分支的强推，**必须由用户亲自执行**。
3. 重新执行 §5 预检，确认 `go test` 结果。

## 7. 不得放置的内容

令牌、密钥、凭证、真实个人/客户数据、专有代码、大文件、生成物、Kowa 证据；GitHub Actions 工作流、Webhook、Secret、Deploy key（除非阶段明确需要，且先登记在本目录，见 §8 的“CI 观测”）；任何 Kowa 源码副本。

### CI 观测

沙箱目前没有任何 Actions；`commits/<sha>/status` 因此返回 `state:"pending", total_count:0`（“无检查”看起来像“检查中”）。S05 若要验证 CI 事实读取，需要一个最小工作流和用户批准，且须把“无检查”与“检查中”区分作为负向用例。
