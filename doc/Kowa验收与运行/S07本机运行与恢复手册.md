# S07 本机运行与恢复手册

> 本文件只登记本机 Server/Runner MVP 的运行、观测、备份恢复口径与验收水位；阶段状态以后端 `总体设计与进度.md` 为准，下一动作以接力卡为准。
> 本文件不写 SLA、不写未实测的数字；每一项"未实测"都直接写明。

## 1. 适用范围与本机边界声明

- 适用：单 macOS 账号、单机 Server + 单 Runner、本地 PostgreSQL 17.11 与本地 Artifact Store 的开发/验收环境。
- **边界声明（实测，非推测）**：Runner 与模型 CLI 运行在同一个 macOS 账号下。Runner 只把显式白名单变量交给 worker（默认 `PATH,HOME,LANG,LC_ALL,TERM`），因此 **worker 继承 `HOME`**，从而可读取该账号的 `~/.config/gh/hosts.yml`、`~/.ssh/*`、Codex/Claude 登录态与其他任务目录。**单 macOS 账号不是硬隔离边界**，TaskSpec 与提示词也不构成 GitHub 层硬拦截。
  - 该结论由 `test/security/worker_environment_test.go`（绑定真实 `runner.BuildWorkerEnvironment`）与 `scripts/test-recovery-drill.sh` 的假凭证探针共同取证；探针只用合成凭证，不使用真实令牌。
  - 越界试验一律使用**假凭证与隔离数据**；真实令牌、私钥、会话 cookie 不写入方案、日志、截图或 record。
- 不适用：生产部署、多机 Runner、共享物理实例的 Langfuse 生产规格。本手册不构成生产就绪声明。

## 4. 健康与水位（操作前必须先冻结）

- `GET /healthz`：进程存活，恒 `{"status":"ok"}`。
- `GET /readyz`：就绪。数据库可达 → `200 {"status":"ready"}`；否则 `503 {"status":"unavailable","reason":…}`。**评测后端不可用不改变就绪结论**：它是观测后端，不是交付前置。
- `GET /api/v1/observability/health`（session）：构建提交、迁移版本、Go 版本、数据库可达性、评测后端可用性与 spool 深度、本进程自身水位。
- `GET /api/v1/workspaces/{workspaceID}/work-items/{workItemID}/observability/watermarks`（session+member）：该工作项的冻结水位——定义名/版本/digest、执行配置版本、运行计数、Runner 联系水位、业务进度水位、每个外部观察主题的最后尝试与是否已知、Artifact 命名空间。

**冻结水位的三条语义**（由 `api/observability/v1` 冻结，不是约定）：

1. **心跳不等于业务进度**：`runtimes[].contactable` 只由 Runner 联系决定；`progress` 只由运行自身事实派生。联系正常、运行停滞时 `progress.freshness=stale`。
2. **旧观察不冒充新事实**：`observations[].lastAttemptKnown=false` 时 `freshness` 必为 `stale`/`unknown`，并给出 `freshnessReason`；失败不会刷新成功时间。
3. **水位里没有凭据**：自由文本字段一律 `SafeText`，命中凭据形状即被契约拒绝。

观测口径补充：日志经进程级采集前脱敏（`observability.LogAttr`，覆盖 control plane 与 Runner 两个进程）；评测记录落本地 spool（`$KOWA_MATERIALIZE_ROOT/evaluation-spool`），**spool 丢失只损失轨迹，不影响任何业务事实**。

## 5. 评测后端（Langfuse）接入口径

- 传输：`POST {base}/api/public/otel/v1/traces`，`Content-Type: application/json`（OTLP/HTTP JSON），`Authorization: Basic base64(publicKey:secretKey)`，`x-langfuse-ingestion-version: 4`；健康探测 `GET {base}/api/public/health`。以上为冻结契约，由 `internal/evaluation/langfuse/client_test.go` 逐请求断言。
- 实现不含新增 Go 依赖：OTLP/JSON 由标准库手写编码，未引入 OpenTelemetry SDK。
- 分类：网络失败与 5xx → `unavailable`（可重试）；其余非 2xx → `rejected`（永久，不重试）。
- 同一条记录重投使用同一 trace/span，所以重试更新一个对象，不会创建第二个。
- **同步门禁与异步评测分离**：`sync_gate` 必须取得后端确认，后端不可用即"未满足"并记录恢复条件，永不降级为假定通过；`async` 失败只记录状态与重试，永不改变交付状态。Langfuse 无任何读回路径。
- **实测水位（2026-10-16）**：本机 Docker `MemTotal≈4.8 GiB`；官方自托管最低要求合计约 23 GiB（Web 4 GiB + Worker 4 GiB + PostgreSQL 4 GiB + Redis/Valkey 1.5 GiB + ClickHouse 8 GiB + Blob 4 GiB）。**本机当前不具备运行真实 v3 实例的资源条件**，因此真实实例的版本/资源/保留期**尚未在本机实测**，不得写成已冻结；自动证据为进程内假 OTLP collector 的正反用例。

## 6. 本机运行编排

```bash
# 1) 隔离 PostgreSQL（一次性容器，用后即删；只清理自己创建的容器）
docker run --detach --rm --name kowa-local-pg \
  --publish 127.0.0.1:5432:5432 \
  --env POSTGRES_DB=kowa --env POSTGRES_USER=kowa --env POSTGRES_PASSWORD=kowa-local-password \
  postgres:17.11-alpine
for migration in db/migrations/*.up.sql; do
  docker exec --interactive kowa-local-pg psql --username kowa --dbname kowa --set ON_ERROR_STOP=1 < "$migration"
done

# 2) 控制面
export KOWA_DATABASE_URL='postgres://kowa:kowa-local-password@127.0.0.1:5432/kowa?sslmode=disable'
export KOWA_MATERIALIZE_ROOT="$PWD/.run/materialize"
export KOWA_IDENTITY_ENABLED=true KOWA_WEB_ORIGIN=https://127.0.0.1:8443
export KOWA_GITHUB_CLIENT_ID=... KOWA_GITHUB_CLIENT_SECRET=...
export KOWA_RUNTIME_ENABLED=true KOWA_RUNTIME_CREDENTIALS="runtime-local-1=<≥16位令牌>"
go run ./cmd/server

# 3) Runner（本机 Provider CLI 由该账号已安装/已登录的能力提供）
export KOWA_RUNNER_SERVER_URL=http://127.0.0.1:8080
export KOWA_RUNNER_RUNTIME_ID=runtime-local-1 KOWA_RUNNER_RUNTIME_TOKEN=<同一令牌>
export KOWA_RUNNER_WORK_ROOT="$PWD/.run/runner" KOWA_RUNNER_PROVIDER=claude
export KOWA_RUNNER_CAPABILITIES=plan.create@1,code.generate@1
export KOWA_RUNNER_GITHUB_USER_ID=<机器账号十进制 id>
go run ./cmd/runner

# 4) 就绪与水位
curl -fsS http://127.0.0.1:8080/readyz
```

停机：先停 Runner，再停控制面（SIGINT 触发优雅退出并打印 `server stopping`/`runner stopping`）。

## 7. 备份与恢复

备份目录布局（冻结）：

```
<backup-dir>/manifest.json
<backup-dir>/postgres/database.pg_dump
<backup-dir>/artifacts/…
<backup-dir>/runner-state/…
<backup-dir>/config/config.snapshot        # 仅变量名，绝不写值
```

```bash
# 备份：必须先停止控制面与 Runner（写入方静止），再记录一致性点
KOWA_BACKUP_POSTGRES_CONTAINER=kowa-local-pg \
KOWA_MATERIALIZE_ROOT="$PWD/.run/materialize" \
KOWA_RUNNER_WORK_ROOT="$PWD/.run/runner" \
bash scripts/backup-local.sh --dir /tmp/kowa-backup-1 \
  --consistency-point "control plane and Runner stopped at <UTC> before pg_dump"

# 校验（恢复前必做；摘要不符一律拒绝）
bash scripts/backup-manifest.sh verify --dir /tmp/kowa-backup-1

# 恢复：先校验、后写入；不删除目标侧任何内容
KOWA_RESTORE_POSTGRES_CONTAINER=kowa-local-pg \
KOWA_MATERIALIZE_ROOT="$PWD/.run/materialize" \
KOWA_RUNNER_WORK_ROOT="$PWD/.run/runner" \
bash scripts/restore-local.sh --dir /tmp/kowa-backup-1 --dump-dir /tmp/kowa-restore-1
```

规则：

- `BackupManifest` 逐组件记录 `sha256`、文件数、字节数与一致性点；清单自身有覆盖全字段的 `manifestDigest`，改一个字段即失效。
- `restore` 在**写入之前**校验：先验清单、再逐组件重算摘要；任一不符即停并指名组件。
- 恢复后的目标目录会**被重新计算摘要**并与清单比对，所以恢复到混有其它内容的目录会被拒绝（清理目标目录是操作者的显式决定）。
- 恢复**不删除**仍被运行或关闭证据引用的内容；Artifact 与 Runner 状态按文件恢复，`postgres/` 由 `psql` 应用。
- **RPO 基线**：本流程要求先停写入方再 dump，因此已提交事务不丢失（实测见 §9）。不停写入方直接 dump 会产生撕裂快照，不属于本流程。
- **RTO**：实测值见 §9；未在本机复跑过的时间不得引用。

## 10. 真实验收所需水位与操作清单（供 S08 使用）

进入 S08 真实跨端验收前，操作者需要冻结并保留：

1. Kowa HEAD 与实际构建提交（`/api/v1/observability/health` 的 `deployment.commit`），迁移版本（同接口 `migrationVersion`）。
2. 定义身份：`kowa-fixed-workflow@1` 的 `digest`（同接口 `definition.digest`）。
3. 执行配置版本（同接口 `executionConfigVersion`）与 Runner 能力清单、Provider 版本、`KOWA_RUNNER_ENV_ALLOWLIST` 实际值。
4. 每个主题的外部观察水位（`observations[]` 的 `lastAttemptAt` 与 `lastAttemptKnown`）——**运行前与运行后各取一次**。
5. Artifact 命名空间（`artifacts.namespace`）与已发布数量。
6. 仓库身份与协议（`KOWA_REPOSITORY_REGISTRY` 的 id 列表、`git ls-remote` 协议）、CI 规则、个人 `gh` 身份与 git remote 协议。
7. 该次运行的备份（§7）与演练结论（§8）；观测后端真实实例若不可用，如实记为观测缺口，不当作交付阻断。

需要用户执行的操作（AI 不代做）：安装/启动 Docker Desktop 与外部依赖、启动自托管 Langfuse 实例、写入真实 Langfuse 密钥、变更本机凭证或服务配置、GitHub App 安装与授权、触发真实 WorkflowRun/Runner 派发、合并 PR。

## 11. 风险声明

- **不是硬隔离**：见 §1；本机边界以 §9 实测为准，任何"已隔离"表述都不成立。
- **不是生产部署**：本手册只覆盖单机开发/验收；容量、并发、RPO/RTO 承诺与高可用均未建立。
- **Langfuse 不是状态真源**：轨迹与评分不参与任何交付判定；其不可用只影响观测完整性。
- **spool 是可丢弃的本地观测存储**：无备份义务，丢失不等于业务事实丢失。
- **凭证治理**：真实令牌/私钥不入库、不入日志、不入证据；如发现疑似泄漏，先按 §8 跑 `check-secret-leaks.sh` 与定向测试，再决定是否重开责任阶段。
