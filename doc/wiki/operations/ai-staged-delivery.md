# AI 分阶段交付规则

本文定义前后端共用的阶段合同、执行记录和并行施工规则。阶段状态仍只在各端 `总体设计与进度.md` 中维护。

## 1. 阶段成立条件

一个阶段必须同时满足：

1. 只有一个可验证的工程目标。
2. 前置依赖和共享契约版本明确。
3. 允许修改范围与禁止范围明确。
4. 能通过自动验证或受控人工操作独立验收。
5. 完成后能在新会话中恢复，不依赖聊天隐式上下文。

阶段编号只表达本端顺序。跨端依赖必须使用 `backend:Sxx`、`frontend:Sxx` 明确引用，不能依靠相同编号推断关联。

## 2. 计划、状态、接力与证据

- 各端 `总体设计与进度.md`：唯一阶段状态与依赖表。
- `stage/Sxx-*.md`：施工合同，只写计划、范围、验证和退出条件，不维护状态。
- `当前阶段与下一步.md`：最近会话继续点和人工操作清单，不拥有状态。
- `record/Sxx.md`：只追加真实执行事实、命令、证据、偏差和阶段结论，不复制计划。
- `doc/当前进展.md`：跨端只读指针，不拥有任何阶段状态。
- 阶段合同的“推荐 Skills”只提供任务路由和工程参考，不是业务或阶段退出权威。执行者按实际问题选择，可增加或跳过；record 记录实际使用与跳过原因，Skills 不得覆盖 `AGENTS.md`、冻结契约或阶段修改范围。

模板分别见 [阶段合同模板](stage-template.md) 和 [执行记录模板](record-template.md)。

## 3. 绿地与存量修改

修改既有行为时，先建立 characterization 测试，再以目标红灯证明目标契约尚未满足。

纯绿地阶段没有旧行为时，在阶段文件和 record 中记录“不适用”及依据，直接从目标契约和目标红灯开始。不得为满足模板伪造旧行为或旧问题。

## 4. 跨端与并行施工

- 后端 lane 与前端 lane 可以各自拥有一个活跃阶段；同一 lane 始终只有一个 `currentStage`。
- 每个实施会话或 Agent 只绑定一个阶段和一个隔离工作区；同一阶段内并行时必须共享阶段合同并划分不重叠写范围。
- 不同阶段的并行只允许发生在不同 lane；不得并行修改同一权威文档、共享契约或同一源码所有权范围。
- 共享契约只有一个 owner 阶段。消费者阶段依赖冻结版本，只能实现消费侧，不得重新解释业务语义。
- 含跨端阶段依赖的消费者合同必须填写具体 owner 阶段和冻结版本或内容摘要；消费者进入 `IN_PROGRESS` 前，所依赖的跨端阶段必须为 `DONE`。只存在状态行、口头确认或未冻结候选 schema 均不满足门禁。
- 前后端能够并行的前提是契约已冻结、写范围不重叠且各自具备独立红灯。
- Join 验收必须由显式阶段负责，不能以“两个阶段各自通过”代替端到端验证。
- 发现重叠修改、契约漂移或前置结论失效时立即停止，并按状态机回到权威 owner。
- 返工中发现更早责任阶段失效时，当前返工 owner 转为 `BLOCKED` 并写入 `suspendedReopen`，更早 owner 成为唯一 `currentStage`；暂停 owner 不得继续施工。只允许一层暂停，出现第三层时停止并做显式状态审查。

## 5. 阶段退出

只有以下条件全部具备才能将阶段标记为 `DONE`：

- 阶段目标和退出条件逐项有证据。
- 共享契约 owner 阶段已发布机器 schema、版本或内容摘要、正反样例、Producer/Consumer 核对、失败语义及验收矩阵映射；不拥有共享契约时明确写“不适用”。
- 定向测试、受影响回归、构建和静态门禁通过。
- 必要的真实环境验收已使用新运行和新制品完成。
- record 已记录命令、退出码、测试数量、证据 ID、偏差、风险和未完成项。
- 工作区来源明确，用户预存修改未被覆盖、清理或重新暂存。
- 下一阶段的准入结论已写明；本会话不继续实施下一阶段。

## 6. 交付与消费检查

按 AGENTS.md §5.1 执行，不增加阶段状态。只读审计、方案收敛和获批文档修订可在同一会话完成；生产实施仍绑定一个阶段。

消费者的 `kowa-stage-consumption.v1` 块只记录需求绑定；状态和阶段依赖仍以本端状态表为准。`sha256=null` 表示待冻结，只允许 NOT_STARTED。准入时 pin owner 发布的 `delivery.json` 摘要（其包含 schema 摘要、操作和实际交付层次），并链接正反验收证据。登记文件不定义第二套业务语义。

治理门禁检查依赖一致/无环、owner、实际合同/摘要/操作/层次和证据路径；证据是否充分、生产输出是否正确仍由测试与审阅确认。历史阶段不补造退出证据；新增或重开消费者补齐需求块。owner 新发布或修改合同时提供 delivery.json，并预检直接消费者。
