# Kowa 项目知识库索引

本目录保存 Kowa 的**跨端项目级知识**（“系统现在是什么样”），按主题分类。它不保存阶段状态、实施流水、决策原因或只影响单端的细节。

## 分类

| 分类 | 职责 |
| :--- | :--- |
| `architecture/` | 架构、关键流程与系统边界 |
| `domain/` | 业务实体与领域规则 |
| `contracts/` | API、协议与数据契约 |
| `design/` | 无法归入单一模块的跨端专题设计；不得重复架构、契约或决策记录 |
| `modules/` | 模块与能力边界 |
| `operations/` | 发布、监控、排障与回滚 |
| `glossary/` | 术语与命名 |

## 边界规则

当前 MVP 设计从 [交付流程与范围](design/mvp-delivery.md) 进入；已确认的领域状态与转换见 [交付生命周期设计](domain/delivery-lifecycle.md)。未冻结的候选接口和设计待办见 [设计审阅目录](../research/mvp-design-review.md)，不得当作正式契约。

`doc/wiki/` 只写**跨端共享、前后端都要引用**的当前知识。只涉及单端的内容写入 `doc/Kowa后端设计/` 或 `doc/Kowa前端设计/`。

- 当前共识属于 `doc/common.md`，决策及原因属于 `doc/decision.md`。
- 阶段计划、状态和执行证据分别属于各端 `stage/`、`总体设计与进度.md` 和 `record/`。
- 每篇知识文档只能有一个分类；其他分类通过链接引用，不复制正文。
- 新增、移动或删除知识文档时，必须同步更新所属分类的 `index.md`。
- `index.md` 只维护页面清单和边界，不复制页面内容。

## 页面登记格式

各分类索引使用下表登记正式页面：

| 页面 | 权威范围 | 状态 | 最近核验 |
| :--- | :--- | :--- | :--- |

状态只允许 `draft`、`active`、`superseded`；`superseded` 页面必须链接到替代页面，不得继续作为当前事实引用。
