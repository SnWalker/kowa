backend:S04 退出时对其直接后继登记本准入硬条件；本块只约束本阶段的输入生产/消费边界与验收，不改变本阶段状态或实现范围。

- **唯一 owner**：`run admission` 与 `task → 冻结输入引用` 的**绑定生产者**归 backend:S06（本阶段"允许修改"已含"输入绑定"）。backend:S05 只提供 WorkItem 基础事实与已接受的人工答复（知识确认），不拥有运行准入；本阶段不得把该责任回推给 S05，也不得留"由 S05 或 S06 决定"的模糊表述给消费方。
- **读取用 scope 必须是不可变 OID**：凡用于"被冻结的项目/知识输入"的读 scope，`GitScope.ref` **必须**是 40 位 commit OID；`refs/heads/<branch>` 仅用于获准工作分支的**操作授权**（写），**禁止**以分支最新 tip 替代冻结版本。
- **绑定一致性**：派发时按每个节点冻结的 EffectiveInput（`kowa.knowledge-artifact.v1`）与其上游代码引用，建立一致的 `task → 冻结输入引用 / 项目 commit` 绑定并持久化，使 S04 的输入路由可解析；不得从分支最新值、生产者目录或运行期查询反推。
- **前置 owner 与共享冻结引用**：消费 backend:S03 `kowa.knowledge-artifact.v1`（EffectiveInput/ArtifactRef 与冻结摘要）、backend:S02 `kowa.workflow-execution.v1`（`gitScopes` 形状）、backend:S04 的输入路由与受控 Git 通道（S04 已交付"受权获取 / 摘要校验 / 交付 Worker"消费链）。S04 生产组合根在绑定缺失时 **fail closed**（`RESOURCE_UNAVAILABLE`，`unboundTaskInput`）；本阶段不得以测试桩绕过该拒绝。
- **必须的验收（纳入本阶段目标红灯）**：① 40 位 OID 读 scope 正例（物化 OID 恒等）与非 OID 形态负例；② **分支移动**用例——远端分支前进后同一绑定仍产出同一冻结 OID、输入内容不变；③ **目录删除后按同一冻结引用重建**得到同一 OID；④ 绑定缺失或不可解析时 fail closed 且不派发 Worker；⑤ 拒绝后合法请求仍成功。

### 领域规则（冻结语义）

- **准入唯一性**：一个 WorkItem 同时只有一条推进运行。准入要求 WorkItem `OPEN` 且无 `currentRunId`；准入在持久化运行后调用 S05 `workitem.associateRun`（`kind=initial`）取得推进权，重复准入被唯一约束/版本冲突拒绝。跨 Workspace 的 WorkItem 一律 `FORBIDDEN`，不靠请求参数判断归属。
- **冻结基线**：准入时把项目仓与知识仓的默认分支 head 解析为 40 位 commit OID 并冻结到准入记录。此后所有"读"scope 的 `GitScope.ref` 恒为这些 OID；`refs/heads/<branch>` 只出现在写 scope（工作分支，`⊆ refs/heads/task/kowa-<runId>`）。分支最新 tip 永不替代冻结版本。
- **输入绑定（唯一 owner S06）**：每个被派发的 Task 必须先持久化 `task → 冻结输入引用`，内容为 S03 的 EffectiveInput（canonical 字节的 digest 即 `task.inputDigest`）+ 引用 Artifact 的冻结引用 + 项目/知识 commit OID。Runner 取输入时按绑定读取；无绑定或不可解析一律 fail closed（`RESOURCE_UNAVAILABLE`），不得以测试桩绕过。绑定创建后不可漂移：重试复用同一绑定，重跑建立新绑定。
- **无绑定窗口不派发**：Task 的创建与其输入绑定在同一存储事务内提交；绑定的输入摘要必须等于 `task.inputDigest`，否则拒绝。租约派发只能取得已完成绑定的 Task。
- **知识未确认不派发**：知识推荐由控制面按冻结知识 OID 读取索引产生（读取失败与成功空结果分开，均保留人工确认）；确认答复经 S05 `human_answer` 接受后，S06 调 S03 `ConfirmKnowledge` + `AssembleKnowledgeInput` 生成持久 EffectiveInput。确认前 `plan` 及其下游不得创建 Task。
- **门禁不可绕过**：普通依赖无环；多依赖节点（`test`、`code-review`、`publish-pr`）为 Join，只有全部必需上游 `DECIDED` 且必需门禁通过才 `READY`；必需上游 `SKIPPED` 或非通过 verdict 时不放行（不用 `all_done`/跳过冒充通过）。
- **返修预算**：`plan_review`、`code_review` 各为 `MaxAutoRevisions=3` 的有界返修区域；返修经 S02 `RerunNode` 建立新 NodeRun 轮次（1 初评 + 3 自动修订）并重建受影响下游输入。预算耗尽返回 `POLICY_BLOCKED` 并建立人工处置 HumanTask，不自动放行、不静默重置计数。
- **Retry / Rerun / 取消 / 修复**：Retry 保持有效输入（同一绑定、新 Task）；Rerun 重建受影响节点及下游输入，产生新结果与产物版本；取消先停新派发，在飞租约收束后 `CANCELED`，已发生的外部副作用保留事实、不声称回滚；修复运行要求来源运行已结束，写入 `workitem.associateRun(kind=repair)`，不继承旧批准，原 WorkItem 保持 `OPEN`。
- **关闭唯一权威**：运行 `SUCCEEDED` 与 WorkItem `CLOSED` 只由 S05 `evaluation.AtomicCloser` 单事务提交；S06 的 `delivery.close` 系统节点只调用该端口，不自建成功路径、不把节点自述当门禁。
- **恢复与历史**：进程重启后由持久状态 reconcile 继续（不依赖内存连接或本地目录）；历史轮次与旧任务只读展示，旧结果不推进当前 DAG。知识建议等异步分支失败不阻塞已满足条件的业务关闭。

### 修订（2026-10-15，实施期由代码证据触发）

- **被评审交付物按普通发布物发布**（`requiresApproval=false`）。证据：backend:S03 的 `AssembleKnowledgeInput` 要求上游 Artifact 已 PUBLISHED 且 Approved，而 `plan_review` 必须把 plan 作为执行输入读取；把 plan 登记为未批准候选会使其无法被任何下游节点消费。人类批准门禁因此由 `plan_approval` 节点的 verdict 与 DAG 依赖承载；S03 的"可读候选未批准不可执行"语义仍由 S03 自身测试覆盖，本阶段不重复实现。
- **外部事实/人工门禁的轮次顺序**：引用某个节点轮次的行（`human_task`、`external_operation`）必须先由 `DecideNode(WAITING_HUMAN)` 物化该轮次；被中断的请求由 reconciler 幂等重建（人工请求按冻结 requestKey 复用）。
- **绑定不可变与重试复用**：被中断在某次派发之前的运行重试必须复用同一 `taskId`/`nodeRunId`/`inputDigest`/`deadlineAt`，不得生成第二份意图；绑定差异一律 `VERSION_CONFLICT`。
- **门禁词汇与 `gating` 规则**：`approved` 与 `passed` 是仅有的两个"门禁满足"verdict，其余（含空 verdict）一律不满足。一个上游是否按 verdict 判定，由能力目录声明决定：能力输出 schema 声明 `verdict` 字段者为门禁节点，必须通过；只产出内容的节点"已决定"即满足其下游。
- **上游与字段唯一性**：同一声明节点内的多个绑定若指向同一生产者，EffectiveInput 的 upstream 只出现一次（S03 拒绝重复 upstream 名）；必需上游名单同样去重。
- **外部写意图的轮次前置**：引用节点轮次的外部事实（`external_operation`、`human_task`）必须在轮次已存在之后写入；需要轮次但没有 Task 的控制面路径使用 execution 侧最小只开轮次端口 `OpenNodeRound`（只产轮次、不产 Task，随后由 `DispatchNode` 把尝试挂到同一轮次）。
- **标识符语法**：Workspace/WorkItem/HumanTask 等会作为 S03 的 `scope`/`subject`/上游引用进入知识合同的身份，必须满足 artifact 标识符语法（`^[A-Za-z0-9][A-Za-z0-9_.:-]{0,199}$`）；组合根为这些身份提供十六进制生成器。
- **读 scope 必须是不变提交**：派发端口在服务端校验——`clone`/`fetch`/`pull` 的 `ref` 必须是 40 位 commit OID，`refs/heads/<branch>` 只允许作为写操作授权（`commit`/`push`/`publish_pr`）；分支持续前进不改变任何已冻结输入。
- **决定与返修各一次**：一个评审轮次的返修只开启一次（目标节点当前轮次已领先该决定轮次时不再开启）；被接受的答复即使续接意图已被消费，也必须幂等地落到该轮次的决定上。
- **返修区域的重评与下游重建**：被审目标开新轮后，判定者自身必须按预算重新物化（`1 初评 + 3 自动修订` 因此可达，耗尽转人工处置）；Rerun/返修使上游轮次前进时，已物化下游中引用了被取代轮次的轮次必须重建为新轮次（旧轮次与旧尝试保留，旧结果不再满足门禁）。
- **知识确认被拒后的再询问**：被拒的确认在新的确认轮次重新询问；推荐行始终指向待决确认请求（未确认时可被新一轮请求替换，确认后绑定最终请求、不再替换）。
- **人工预算批复是显式决定**：预算耗尽建立绑定到区域（`<run>:<decider>`）的 `revision_escalation` HumanTask；已批准答复是持久决定，由推进过程消费为"该区域增加一轮"，不是静默清零、也不是无人消费的任务。
- **绑定不可变按全部字段判定**：`task → 冻结输入` 绑定的任一身份/输入/仓库/能力/Provider/scope/制品/截止时间字段漂移一律 `VERSION_CONFLICT`，只有完全相同的冻结意图才幂等重放（`BoundAt` 是首次持久时间，不属于意图）。
- **辅助知识建议异步分支（A26）**：迁移 000006 第六表 `knowledge_suggestion`（经 Coordinator `approve-with-changes` 批准，见 record 裁定）。语义：close 提交前先持久 PENDING 事实（关闭绝不等 artifact 生成/上传）；独立 worker（与运行推进分离、有界上下文）按 claim 租约处理（`PENDING`/过期 `PROCESSING` 可认领，`version` fencing 拒绝迟到写入）；成功发布 `knowledge_suggestion` 类型 Artifact（真实 artifact 服务，绝不写知识仓）并记 S05 `knowledge_suggestion` 辅助 evidence（`ProducerID=attempt 身份`，幂等镜像）；失败如实记录失败原因且不阻断关闭；`run.recovery` 新 kind `retry-knowledge-suggestion`（不接受 `nodeId`，仅当 item `CLOSED`、本运行是 closure 来源且 `SUCCEEDED`）只开启下一次辅助尝试，不新建轮次、不改业务/关闭事实，同 `requestKey` 同内容重放优先于状态检查；`run.detail-history` 输出 `knowledgeSuggestion` 摘要与逐次尝试历史（append-only，旧失败不被覆盖）。
- **publish_pr 写意图按交付身份冻结**：`external_operation` 的 RequestKey 为 `run + 被交付 commit`，使同一运行在代码返修后的第二次交付拥有自己的写意图序列，不再与首次发布冲突。
- **冻结 commit 读视图按 commit 隔离**：物化器对同一仓库的每个冻结 commit 建立独立 `git worktree` 检出（视图不可变）；分支前进、并发打开其它 commit、删除本地检出后按同一 OID 重建均返回恒等内容。
- **首期知识集合等于冻结索引**：推荐/确认只在冻结索引（`kowa-index.json`）内进行（可增删/筛选/确认，`required` 不可删，索引外条目一律拒绝）；索引外自由新增不属本阶段，前端消费阶段按其准入时冻结的契约解释（消费者预检见 record）。
- **Retry 保持有效输入的含义（细化既有"同一绑定、新 Task"）**：保持的是同一 EffectiveInput、输入摘要、上游冻结引用、能力与 Provider、scope；每个新尝试持有自己的不可变绑定行（旧行不改），任务身份与截止时刻属于新的派发意图。截止时刻仍在未来的失败尝试沿用冻结截止时刻；截止时刻已过（无论 FAILED/EXPIRED 还是 QUEUED 过期）时，由 S06 自有的 additive 应用操作 `RetryAttempt`（同 `DispatchNode` 系列，经 Coordinator 批准）在服务端固定 horizon 下生成**一次**新截止时刻并持久化：QUEUED 过期先在同事务内收束为 EXPIRED 再建下一尝试；未过期 QUEUED、LEASED/RUNNING（须先经既有 sweep 结算）、AWAITING_INPUT 与已结算成功尝试一律拒绝；同身份同内容幂等重放（即使新截止时刻后来又过期或运行版本前进），异内容冲突；新截止时刻必须仍在未来，绝不返回"Applied 但永久不可领"。旧输入、旧截止时刻与旧结果历史不变；客户端不得传入截止时刻。
- **陈旧只按冻结因果引用判定**：一个轮次是否陈旧，只由它自己冻结的因果引用决定，不比较任何节点的局部计数。能力轮次把完整引用集冻结在其 `task_input_binding` 的 `causal_refs`（每个依赖门禁的轮次、每个声明的输入生产者的轮次与交付物身份）并在判定时逐一与当前轮次身份比对；控制/人工轮次用其冻结输入摘要（现按相同identity集合计算）与按当前上游重算的结果比较。判定递归：被引用轮次本身不新鲜时其下游同样不新鲜。下游被人工 rerun 到与上游新轮相同或更高的编号、或下游计数低于上游时，只要引用一致就判新鲜（重复 reconcile 不产生新轮/任务/外部意图），引用被取代就重建；缺绑定、引用不可读或上游轮次缺失等无法判定新鲜的情形一律 fail closed（当前 pass 报错重试，绝不把不可判定当作新鲜放行）。纯依赖门禁（如 plan_approval）被单独 rerun 时，即使数据制品未变，其下游也即刻失效，并在新门禁决定到来前不被放行、之后按引用一致重建。
- **陈旧下游重建必须过依赖门禁**：被上游新轮取代的轮次只有在**每个依赖已决定、门禁通过且其自身不是等待重建的陈旧轮次**时才重建；被重新询问的人工批准（如 plan_approval 新轮）在其答复到来前保持其下游全部关闭（不派发新版输入的下游尝试）；`askForRevision` 直接开启被审节点新轮的路径不受此检查影响（无死锁）。
- **被取代的人工请求会过期**：重问 plan 批准时按 S05 已有的版本域过期规则（`ExpireBoundTo`，kind=`plan`、`exceptVersion`=新 plan 摘要）把旧 OPEN 请求置为 `EXPIRED`；旧请求的答复被 S05 拒绝，新请求照常可答。同一取代路径下不再留下陈旧幽灵请求。
- **无声明自动返修区域的节点（test/security_review/integration）报 `needs_revision`**：不自动返修；耗尽升级任务绑定该节点自身，人工批准的答复被显式消费为"该节点增加一轮"（自目标 grant，复用既有 grant 消费机制），拒绝则不放行、不再为该区域自动升级（唯一人工出路=取消或修复运行）；不存在无人消费的幽灵任务。
- **辅助建议发布的硬上界与终态失败**：artifact 发布步骤在 5s 独立有界上下文内运行（不改 S03 自身 workspace 锁语义；同 workspace 的 artifact/knowledge 读写与 workspace 外键写入在该尝试持锁期间同样被串行化，有界于该上界；已 ready 的关闭不受辅助分支影响）；上界触发时以不被取消的上下文把尝试终结为 `FAILED`（保留失败 evidence），worker 不自动重试——只有显式 `retry-knowledge-suggestion` 才开启下一次尝试。
- **同 commit 视图复用**：物化器对同一冻结 commit 的健康检出（`.git` 存在、HEAD 等于该 commit、工作树干净）直接复用，仅在缺失或损坏时重建；并发仍在读取的活视图不被后到的同 commit Open 抽走。
- **答复经 S05 单任务读取得**：S05 的 List 投影不保证携带已接受答复（PG 适配器不携带、Memory 携带，属投影差异）；消费答复（预算 grant、批量扫描）一律经 `humantask.Get` 读取权威详情，不依赖 List 的 Response。
- **无合并事实的运行不支持修复**：`repairBaseline` 只接受已关闭交付的合并提交或本运行已对账的合并事实；合并前被取消的运行没有修复入口，其 WorkItem 按 S05/S08 边界以取消+新工作项处理（如实边界，不声称可走通）。
