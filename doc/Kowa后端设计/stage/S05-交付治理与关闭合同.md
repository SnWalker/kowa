### 冻结契约与操作

`kowa.workitem.v1`（owner backend:S05，manifest `api/workitem/v1/delivery.json`）：

| operation | 层次 | 形状 |
| :--- | :--- | :--- |
| workitem.intake | http | `POST /api/v1/workspaces/{workspaceID}/work-items`；session+member(developer/admin)+CSRF；创建 OPEN，冻结目标/需求/验收版本；不启动流程 |
| workitem.list | http | `GET /api/v1/workspaces/{workspaceID}/work-items`；session+member |
| workitem.detail | http | `GET /api/v1/workspaces/{workspaceID}/work-items/{workItemID}`；session+member |
| workitem.cancel | http | `POST /api/v1/workspaces/{workspaceID}/work-items/{workItemID}/cancel`；session+member(developer/admin)+CSRF；OPEN→CANCELED，存在未决/未知外部操作时拒绝 |
| workitem.associateRun | application | 当前运行关联/修复接替端口；唯一生产者 backend:S06（run admission 调用）；前置校验由 S05 服务执行 |
| workitem.close | application | 关闭端口：ClosureEvidence 校验 + run SUCCEEDED + WorkItem CLOSED 同一权威事务 |

`kowa.delivery-governance.v1`（owner backend:S05，manifest `api/delivery-governance/v1/delivery.json`）：

| operation | 层次 | 形状 |
| :--- | :--- | :--- |
| human.list | http | `GET /api/v1/workspaces/{workspaceID}/human-tasks`；session+member |
| human.detail | http | `GET /api/v1/workspaces/{workspaceID}/human-tasks/{humanTaskID}`；session+member；响应携带服务端判定的可用动作 |
| human.response | http | `POST /api/v1/workspaces/{workspaceID}/human-tasks/{humanTaskID}/responses`；session+member+候选/指派授权+CSRF；仅 `kowa_answer` |
| delivery.query | http | `GET /api/v1/workspaces/{workspaceID}/work-items/{workItemID}/delivery`；session+member；PR/Review/CI/merge/验证/关闭/修复运行只读投影 |
| gitRemote.status | http | `GET /api/v1/workspaces/{workspaceID}/git-remote-status`；session+member；只读真实观测的 remote 可用性与权限事实（见下） |
| github.verifyChange | application | 受控交付 `verify_change` 准入与结果接受；生产者 = Runner 受控 Git 通道（经 S02 任务结果交付事实），接受者 = 控制面 |
| github.publishPr | application | `publish_pr` 准入（必需测试+独立评审有效）+ 结果接受；执行者 = Runner 独立能力；控制面只拥有准入与事实接受 |
| github.observe | application | PR/Review/checks/merge 只读对账；未知先查证再重试；重复观察不重复推进 |
| verification.record | application | VerificationEvidence 生产端口（真实/模拟来源、被测版本、生产者身份） |
| delivery.close | application | 关闭端口（与 workitem.close 同一事务入口，登记于本族，供 workflow 关闭用例消费） |

消费者绑定规则：消费者 pin `delivery.json` 文件 SHA-256 并同时核对 `schemaSha256`；不得把 schema 摘要当作 manifest 文件摘要。

### 领域规则（冻结语义）

- WorkItem：`OPEN/CLOSED/CANCELED`；CLOSED/CANCELED 后不可回；同时只有一条交付运行拥有推进权（`currentRunId`）；接替（修复运行）必须携带已结算的前一运行与来源信息，旧运行不得再收普通恢复命令（执行侧命令归 S02/S06；本阶段只持指针与谱系）。创建不启动流程。
- HumanTask：`OPEN/RESOLVED/EXPIRED/CANCELED`；completion mode `kowa_answer`（Kowa 内版本化答复）与 `external_fact`（只由已核对 GitHub 事实收束，不产生 HumanResponse）；请求版本 + 对象绑定（kind/id/version/digest）逐项校验；候选/指派来自服务端；过期请求/对象或 head 漂移使旧任务 EXPIRED，迟到答复拒绝；同 `(actor, task, requestKey)` 同内容幂等、异内容冲突；接受答复与续接意图（`human_task_continuation`，PENDING→CONSUMED 由 S06 消费）同一事务。
- GitHubDelivery：`verify_change` 核对仓库/ref/OID/身份与冻结基线；`publish_pr` 准入要求必需测试通过、独立评审通过、PR 目标/源一致；PR 作者必须是登记的机器身份；Review 必须来自非 PR 作者的有权真人且对当前 head 有效；checks 区分 `none`/`pending`/`failed`/`passed`；merge 事实绑定实际合并提交 OID（不拿目标分支最新 HEAD）；未知结果先按仓库/ref/OID/PR 对账再决定重试；模拟/缺失/陈旧/未知一律不满足门禁；越界报告不撤销已发生的远端副作用（先对账、不假称已回滚）。
- Evaluation/Closure：VerificationEvidence 绑定被测仓库/commit 或 Artifact、配置版本、生产者（Task/外部 CI/评审节点）、真实/模拟来源与结果；ClosureEvidence 逐项绑定需求/知识确认、定义版本/摘要、策略版本、运行、必需测试、独立评审、有效 Review、实际合并与合并后验证；关闭与有效运行 SUCCEEDED 同一权威事务；缺证据/旧 run/版本失配/竞态拒绝；辅助（知识建议、离线评测）失败不阻塞关闭；合并后验证失败保持 WorkItem OPEN，提供受控关联修复运行入口，不自动回滚。

### Git remote 可用性与权限缺口（frontend:S01 缺口，唯一 owner backend:S05）

- 冻结为 `kowa.delivery-governance.v1` 的 `gitRemote.status` 操作，**不修改** `kowa.runtime-web.v1`，不重解释 Runtime 健康/权限。
- 事实分层：Web actor（会话认证的请求者）、登记机器身份（S04 runtime 注册的 `gitHubUserId`）、实际 GitHub 查询身份（真实 `gh api user` 数字 ID）、实际 remote 读取事实（真实 `git ls-remote` 结果与所用传输协议）与权限事实（GitHub API 返回的 viewer 权限）、以及未知/未探测。只有真实观测可声明 available/readable；登录/注册/CLI 存在不构成可用证据；未做真实写入观测时写能力只报权限事实并显式标 `unknown`/`none`。
- 入口：`GET /api/v1/workspaces/{workspaceID}/git-remote-status`（session+member，只读，请求即触发有界真实只读探测）。
- 消费准入治理：frontend:S01 的消费准入块需新增本 owner 依赖条目；按上下文纪律先经 Coordinator 批准限定文档范围，保持前端 NOT_STARTED，不写页面。
