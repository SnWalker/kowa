- **`authorization` 赋值与 scheme 规则的顺序**：首版把 `authorization-scheme` 放在 `secret-assignment` 之前，导致 `Authorization: Bearer <token>` 被拆成两次替换（`Authorization:*** ***`）。修订为赋值规则先行、且消费可选的 scheme 词，输出收敛为 `Authorization:***`。这是本阶段自己引入并当场修正的实现缺陷，不是既有行为。

- **信号传递**：演练的进程启动用 `( … ) &` 记录到的是子 shell 的 PID，SIGINT 到不了真正的服务进程。改为 `( cd …; exec env … ) &`，使记录的 PID 就是进程本身。
