# 后端验证规则

本文定义后端阶段共享的最低验证口径。阶段文件必须把适用条目落实为精确命令，全部结果写入对应 `record/Sxx.md`。

## 1. 开工冻结

至少记录：

```bash
git rev-parse HEAD
git status --short
bash scripts/check-doc-governance.sh
```

涉及 Go 工具链时同时记录：

```bash
mise exec -- go version
```

涉及数据库、Runner 或 WorkflowRun 时，还要记录对应 schema/migration 版本、运行实例、任务与制品水位；具体查询必须由阶段文件定义。

## 2. 自动验证层次

按风险依次执行：

1. 修改既有行为时运行 characterization 测试；纯绿地阶段记录不适用依据。
2. 目标红灯。
3. 修改范围内的定向测试。
4. 受影响包回归。
5. 全量 Go 测试、静态检查和构建。
6. 文档治理门禁与 `git diff --check`。
7. 必要时执行隔离环境集成测试和真实环境只读验收。

Go 工程基座建立后，S00 必须将以下入口固化为仓库命令；在入口建立前，阶段文件不得假称已执行：

- 格式检查；
- `go test ./...`；
- `go vet ./...`；
- `go build ./...`；
- 数据库迁移验证；
- 受影响的集成测试。

## 3. 人工操作

GitHub App 授权、真实 WorkflowRun、真实 Runner 派发、生产迁移和部署遵守根 `AGENTS.md` 的人工边界。进入人工操作前必须记录版本、配置、任务和制品水位；恢复后仅做只读验收。

## 4. 收工检查

```bash
bash scripts/check-doc-governance.sh
git diff --check
git status --short
```

阶段还必须记录定向测试、受影响回归、构建结果、退出码、测试数量、偏差、风险和未完成项。

## 合同证据补充

逐操作核对 owner、冻结引用、实际入口和正反证据；样例/Mock 不替代 producer 验证。后端对实际序列化及多适配器不变量做测试，承诺 HTTP 交付时通过组合根验证；前端关键旅程使用真实控制面和隔离外部适配器。拒错后事实保持正确且合法请求仍可成功，真实到期等合同允许的转换另验。

`bash scripts/check-doc-governance-test.sh` 包含阶段依赖/合同绑定及合法重开自测。治理绿色只证明可形式化条件，不证明消费需求完整或业务实现正确。
